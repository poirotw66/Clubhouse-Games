# 發條守城（Clockwork Keep）

## 類別

串聯拼砌類型

## 概述

發條守城是一款以發條鐵皮玩具為主題的 **築迷宮式塔防**。與「路線畫死、沿路擺塔」的傳統塔防不同，本作的格盤一開始是空的，**塔本身就是牆**：敵人每一刻都走當下的最短路徑，因此玩家放下的每一座塔都在改寫敵人的行進路線。

核心技術是「用最少的錢把敵人的路拉到最長」——擺在哪裡，比擺了什麼更重要。

一條硬規則支撐整個玩法：**不得完全封死出口**。系統在放置前先行驗證，若該次放置會使入口到出口無路可通，則拒絕放置。

> 本作為原創玩法設計，不使用任何既有商標角色或品牌素材。

## 人數與建議年齡

- 人數：1 人
- 建議年齡：10 歲以上

## 所需器材

- **介面**：橫向為佳；支援滑鼠與觸控。
- **操作**：
  - 滑鼠／觸控：點擊底部塔欄選塔 → 點擊格子放置；點擊已放置的塔開啟升級／售出面板。
  - 鍵盤：`1`–`4` 快速選塔、`空白鍵` 召喚下一波、`Z` 撤銷、`P` 或 `Esc` 暫停。
- **計分**：波次、分數、剩餘生命；最佳成績依難度分別存於瀏覽器本機（localStorage）。

## 遊戲目標

在敵人耗盡你的生命之前，用塔構築出足夠長、火力足夠密的迴廊，撐過所有波次。

## 核心規則與機制

### 格盤與路徑

1. 格盤為 **12×8**，左側邊緣為入口、右側邊緣為出口。
2. 地面敵人以 **BFS 最短路** 從入口走向出口；路徑長度相同時取固定的方向優先序，確保行為可重現。
3. 每次放置或售出塔，路徑即時重算，畫面同步更新預覽線。
4. **封路禁則**：若一次放置會使入口到出口不存在任何通路，該放置無效並提示，金幣不扣除。
5. 部分格子為 **固定岩塊**，不可放置、亦不可通行，用於區分地圖。

### 塔

| 塔 | 定位 | 特性 | 對空 |
|----|------|------|------|
| 發條弩台 | 單體均衡 | 中射程、高射速、低單發傷害 | ✗ |
| 齒輪磨盤 | 濺射 | 短射程、低射速、範圍傷害 | ✗ |
| 冰霜噴罐 | 控場 | 不造成傷害，僅施加減速 | ✗ |
| 電磁線圈 | 連鎖 | 昂貴，閃電依序跳躍最多 3 個目標 | ✓ |

- 每座塔可升級 **2 次**（共 3 級），提升傷害與射程。
- 售出退還已投入成本的 **70%**（無條件捨去至整數）。
- 鎖定優先序固定為「射程內最接近出口的敵人」，確保結果可重現。

### 敵人

| 敵人 | 特性 | 設計用意 |
|------|------|----------|
| 步兵玩偶 | 基準速度與血量 | 基準 |
| 疾走鼠 | 高速、低血 | 逼玩家佈置減速或前段火力 |
| 鐵皮兵 | 高血、**固定減傷護甲** | 使高射速塔幾乎失效，需濺射或高單發傷害 |
| 紙鳶 | **飛行，無視迷宮走直線** | 火力不能全押在迷宮末端 |
| 首領 | 第 10、20 波各一，高血並帶護甲 | 檢驗整體配置 |

- **護甲為固定減傷而非百分比**：每次命中先扣除固定值再結算，故低單發傷害的高射速塔對鐵皮兵收益極低。此為刻意設計，用以強迫換塔而非堆疊同一種塔。
- **飛行單位不受封路禁則與迷宮影響**，自入口沿直線飛向出口。

### 減速

- 減速**取當前最強者生效，不相乘疊加**，並設有下限（速度不低於基準的 40%）。此規則避免多座冰霜噴罐將敵人永久鎖死。

### 波次與經濟

1. 挑戰模式共 **20 波**；波次組成由固定表格決定，可重現。**無盡模式**在 20 波之後每波複利提升敵人血量，並每 10 波持續產生首領——原本首領波次是寫死的 `{10, 20}`，代表無盡模式從第 21 波起再也不會出現首領，也就是唯一有像樣血量與護甲的敵人，在「永不結束」的模式裡消失了；血量也完全不成長。實測六種對空組合全部撐過 60 波、擊殺數彼此相差不到 0.1%。修正後同樣六種組合分佈在第 31 至 60+ 波。
2. 生命 **20**；一般敵人抵達出口扣 1，首領扣 5。生命歸零即敗北。
3. 金幣來源：**擊殺獎勵**（主要）、波次結算獎勵、**強行加壓加成**。
4. **強行加壓**：在一波**完全湧出之後、尚未清乾淨之前**，把下一波直接疊到這一波上面，依場上剩餘敵人數換取金幣。
   - 這條規則原本寫的是「在準備時間結束前提前召喚，依剩餘秒數給金幣」。實測那是一個沒有代價的按鈕：準備階段不產生任何收益，塔也可以在戰鬥中蓋，所以剩餘秒數的機會成本是零——按下去永遠是對的，而它佔了全局收入的 **56%**。一個永遠該按的按鈕不是決策。
   - 改成依「未解決的敵人數」計價之後，加成才真的對應風險，也才符合「主動壓縮時間換取資源」的原意。實測降到全局收入的 **5–6%**，擊殺獎勵回到主要來源（**67–74%**）。
   - **必須等這一波全部湧出才能加壓**，否則可以逐幀連按：每按一次疊一波、領一次獎金，二十幀就能推到第 20 波而場上還沒有任何敵人（實測 19 次擊殺得到 32,828 分）。這條限制讓堆疊最多一層，且無法連鎖。

### 撤銷與預覽

- **撤銷（Undo）**：在該波尚未開始前，可撤銷上一次放置或升級，全額退還金幣。
- **路徑預覽**：選定塔種後，將游標移至格子上即時顯示「若放置於此」的敵人新路徑與新路徑長度，作為 Hint。

## 輸贏判斷

- **勝利**：挑戰模式撐過第 20 波，且生命大於 0。
- **敗北**：生命歸零。
- **計分**：分數 = 擊殺分 + 剩餘生命 × 係數 + 未花費金幣 × 係數；強行加壓期間分數倍率提高。
- **紀錄**：各難度的最高波次、最佳分數與通關最短時間保存在瀏覽器本機（localStorage）。

## 模式與難度

- **難度**：悠閒／標準／嚴苛，影響起始金幣、敵人血量倍率與起始生命。三檔實測的生命損失是 **0 / 5 / 12**。
  - 這三個值原本是 `0.8 / 1.0 / 1.3` 血量倍率，其中兩檔落在完全沒有反應的區間。把倍率對生命損失掃描出來（遊戲全確定性，每個值都是精確值而非估計）：`0.80–1.05` 損失都是 **0**，`1.10` 是 5，`1.15–1.20` 是 12–13，而 `1.25` 之後**飽和甚至反轉**（1.40 反而只損失 11）。整個反應只存在於 1.05–1.20 這條窄帶。
  - 也就是說悠閒與標準原本是**同一個遊戲**（都零失誤通關），只有嚴苛有反應，而且是從飽和區的另一側。三檔已移到反應帶上。
  - 這件事原本沒有任何檢查在守——所有既有檢查不是驗規則正確性就是釘住回歸值，**沒有一條在問「這三檔是不是三個不同的遊戲」**。新增的守衛是三邊的：順序必須嚴格遞增、最難的必須構成真威脅、而且**每一檔都必須是通得過的**。三個方向都實測會紅。
- **地圖**：開闊（空曠格盤，迷宮自由度高）／窄廊（固定岩塊構成骨架，考驗補位）。
- **模式**：20 波挑戰（有結局）／無盡（波次持續強化，追求最高波數）。

## 隨機性與決定性

- 波次組成、敵人出場順序與鎖定優先序皆為**決定性**，不使用隨機數。
- 相同的操作序列必然產生相同的結果，使整局模擬可作為平衡工具與回歸測試。

## 操作說明

| 操作 | 滑鼠／觸控 | 鍵盤 |
|------|-----------|------|
| 選擇塔種 | 點擊底部塔欄 | `1`–`4` |
| 放置塔 | 點擊空格 | — |
| 升級／售出 | 點擊已放置的塔 | — |
| 召喚下一波 | 點擊召喚鈕 | `空白鍵` |
| 撤銷 | 點擊撤銷鈕 | `Z` |
| 暫停 | 點擊暫停鈕 | `P` / `Esc` |

## 變體與可選規則

- **限塔挑戰**：僅開放兩種塔，考驗擺位而非資源。
- **一鏡到底**：全程不得售出塔。
- **雙路口**：兩個入口共用一個出口（未來擴充）。

## 本專案實作

- 實作路徑：`Games/Clockwork-Keep/`
- 技術：Vite + React + TypeScript，戰場以 **Canvas 2D** 繪製（格子塔防不需 3D，2D 可保持邏輯純粹且體積小）。
- 架構要點：`src/game/` 為零 DOM 的純邏輯，核心為固定時步的 `step(state, dt) -> state`；渲染層只讀狀態不改狀態。此切分使 `check-*.mjs` 能在無瀏覽器環境下跑完整局模擬，作為平衡工具與回歸測試。

## 參考與備註

- 築迷宮式塔防（maze / mazing tower defense）為公開的玩法類型，本作規則與數值均為原創設計。
- 「不得封死出口」是此類玩法的通用約束，用以避免玩家以完全封鎖取代火力配置。
