How WebMCP powers this game

  1. The page exposes structured game capabilities through document.modelContext.
  2. An AI agent discovers the tools and reads the room state and clues.
  3. It chooses domain actions: inspect, pick up, use an item, or enter a code.
  4. GameEngine validates the action and updates the shared state.
  5. The escape-room UI immediately reflects those changes.
AI Agent→WebMCP Tools→GameEngine→Shared Game State→Escape Room UI
Human Player→UI Controls→GameEngine

Both use the exact same capability layer. The AI isn't clicking buttons or guessing the DOM. This demo has no bundled agent, external MCP server, or remote API.
