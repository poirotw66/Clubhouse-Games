## 大老二（Big Two）

四人各 13 張，輪流出牌壓過上一手，**先出完的贏**。牌名來自它最反直覺的一條規則：**2 最大，3 最小**。

規格文件：[`01-cards/big-two.md`](../../01-cards/big-two.md)

---

## 規則摘要

**大小**：`3 < 4 < … < K < A < 2`，同點數再比花色 `♣ < ♦ < ♥ < ♠`。每張牌的點數＋花色唯一，所以 **任兩張一定分得出大小**，永遠沒有平手。

**出牌**：只有 1、2、5 張三種。沒有單獨的三條或四張——它們只能包在葫蘆與鐵支裡。五張牌型由小到大：順子 < 同花 < 葫蘆 < 鐵支 < 同花順。

**張數必須相同才能壓。** 五張牌型壓不了單張或對子。這條讓「領出權」變成真正的資源：能領出的人決定這一輪比的是什麼規格。

**開局**：持 ♣3 者先出，第一手必須包含 ♣3。**一輪結束**：連三家 Pass，最後出牌者重新領出。

**計分**：剩 n 張，n<8 算 n、8≤n<10 算 2n、10≤n<13 算 3n、n=13 算 4n；**手上每留一張 2 再乘 2**（四張 2 沒出掉就是 16 倍）。

---

## 順子的大小是唯一有爭議的規則

A 只能放在頭尾不能放中間，所以 `A2345` 與 `10JQKA` 成立、`JQKA2` 不成立，這點各方一致。**但順子之間怎麼比大小，坊間有兩套。** 兩種都做成選項：

| 設定 | 順序 |
|------|------|
| **比自己的最大張**（坊間常見，預設） | `A2345`（最大張是 5）最小 → `34567` → … → `10JQKA` → `23456`（最大張是 2）最大 |
| **照序列排**（線上實作常見） | `A2345` 最小 → `23456` → … → `10JQKA` 最大 |

兩種內部都自洽，講清楚就好。測試對兩套各自驗證「十個序列的排名互不相同」以及頭尾各是誰。

## 難度：實測出來的，不是猜的

三種 AI 各跑 400 局，把受測的那個放在座位 0、其餘三席放同一種對手。**四人局的損益平衡點是 25%**：

| 受測 \ 對手 | 簡單 | 普通 | 困難 |
|-------------|------|------|------|
| **簡單** | 26.0% | 5.3% | 2.8% |
| **普通** | 60.8% | 27.5% | 15.0% |
| **困難** | **68.8%** | **34.0%** | 26.5% |

階梯乾淨且可遞移：困難 > 普通 > 簡單，而且每一種對上自己都落在 25% 附近——這是個好用的健全性檢查，對角線歪掉就代表哪裡算錯了。

### 這張表原本沒有誤差範圍，而少了它會讓人用錯的方法讀它

400 局在 p≈0.3 時的 95% 半寬大約是 **±4.5pp**。困難對普通場是 34.0 ± 4.6，普通對普通場是 27.5 ± 4.4——**兩個區間是重疊的**。

我第一次看到這個就下結論說「這張表在 400 局下撐不住那個排序」。**那個推論是錯的。** 用「兩個區間有沒有重疊」來判斷差異，是一個比直接檢定差異**更保守**的檢定，它會把真實存在的效果說成不存在。直接算差異：

```
34.0% − 27.5% = 6.5pp，SE 3.25pp → 2.00 SE，95% 區間 [0.1, 12.9]
```

**剛好越過零。** 是邊際顯著，不是不存在。把局數拉到 1,600 之後收斂成 +7.2pp [4.1, 10.4]（4.5 SE）——排序是真的，400 局只是對那一格來說偏薄。

所以量測腳本現在除了每格的區間，還**直接印出比較的差異與它的區間**，因為那才是這張表真正被拿來讀的量：

```
--- Does a stronger brain actually win more, against the same field? ---
  vs a easy    field: hard over normal  +8.0pp  [1.4, 14.6]   ✓ clears zero
  vs a normal  field: hard over normal  +6.5pp  [0.1, 12.9]   ✓ clears zero
  vs a hard    field: hard over normal  +11.5pp [5.9, 17.1]   ✓ clears zero
  ...
```

**印出兩個區間、讓讀者自己目測，等於邀請他用錯的檢定。**

### 「三種難度不一樣」不等於「三種難度有排序」

原本守這件事的檢查是這樣：

```ts
assert.equal(new Set(logs).size, 3, 'two difficulties played an identical game');
```

它比對三種難度在同一個種子下的**出牌紀錄是否相同**。三個一樣強的腦袋可以輕鬆通過——它區分的是「這不是同一段程式碼」，跟誰比較會贏無關。這個 repo 已經出過一次三段難度實際上只有兩段的遊戲，守它的檢查正是這個形狀。

新檢查把每一階放到下一階組成的對手場裡，要求**差異的區間越過零**。1,000 局是從實測反推的，不是隨手挑的：最弱的那組比較在 400 局是 2.0 SE（離擲硬幣只有一步），1,000 局約 3.5 SE。

驗證方式是把「困難」改成挑**最差**的出法——三種難度依然打出不同的牌，所以舊檢查照樣是綠的：

```
  ok   difficulties differ
  FAIL difficulties are ordered, not just different: against a normal field,
       'hard' won 0.2% against 'normal' at 25.6% — a difference of -25.4pp
       with a 95% interval of [-28.1, -22.7], which does not clear zero.
```

順帶查了兩個看起來可疑的地方，**兩個都是假警報**：`if (!result) continue` 之後仍然除以 `N`（會把每個平均值靜靜地往下拉），以及 `playsFor(state)[0]` 這個 fallback。實測 3,600 局裡**未完成 0 局、fallback 觸發 0 次**，最長的一局 90 手對上 400 手的上限。除數還是改成實際計數，因為那是不用付代價的正確寫法——但它修的不是一個現存的缺陷。

### 「高手應該懂得保留牌型」——實測是錯的

困難版的核心是 `turnsToEmpty()`：估算這手牌不受干擾要幾輪才出得完。13 張一張一張出是 13 輪，切成兩組五張＋一對＋一張單張只要 4 輪（實測隨機 13 張平均 6.80 輪）。每個候選出法都用「出完之後剩下的牌還要幾輪」來評分。**這部分有效。**

然後我加了一條聽起來一定對的規則：**如果壓過這手要拆掉一組已經成形的五張牌，就寧可 Pass。** 這是這個檔案裡傷害最大的一行：

| | 對上普通的勝率 | 結束時平均剩牌 |
|---|---|---|
| 會為了保牌型而 Pass | **19.4%** | 5.33 張 |
| 拿掉這條 | **33.0%** | 2.71 張 |

19.4% 在四人局是遠低於平衡點的，**它比普通還爛**。原因是大老二是一場競速，**你放掉的每一輪，都是白送給另外三家的一個回合**。手牌形狀漂不漂亮，遠不如節奏重要。

所以困難版現在只要壓得過就一定壓，拆牌的判斷只用在「壓得過的那幾種出法裡挑哪一種」。

## 介面

點手牌選取，畫面隨時顯示 **目前選取構成什麼牌型、以及壓不壓得過**——壓不過時會講清楚是張數不對、還是單純比較小。

這是報告你已經做的選擇，不是幫你做選擇。**提示鍵**會直接幫你選一手合法的牌，但那是要按才有。

## 邏輯自我測試

`npm run check` 共 16 項。最重要的一項是 **牌型比較必須是全序**。

任兩手同張數的牌都必須分得出勝負、而且不能互相都贏。排序寫錯不會崩潰——它會產生一種「某手牌莫名其妙壓不過任何東西」或「某手牌壓得過自己」的遊戲，而且從頭到尾不會有任何錯誤訊息。這項在兩套順子規則下各抽樣 400 手窮舉比較。

順帶一提，這項第一次跑就抓到我 **測試本身** 寫錯：它拿 ♣3♠3 跟 ♥3♠3 比，兩者都以 ♠3 為最大張所以同分。但一副牌裡這兩手不可能同時在兩個人手上，**這個情況根本不會發生**——所以是測試要排除重疊的牌組，不是規則要改。

其餘涵蓋：2 最大 3 最小且 52 張牌的強度互不相同、七種牌型的判定、三張與四張不是合法出法、A 在中間的假順子（`JQKA2`／`QKA23`／`KA234`）必須被拒絕、五張牌型的階級（用最小的牌組成強牌型去壓最大的牌組成弱牌型）、葫蘆比三條而不是比對子、鐵支比四張而不是比帶牌、張數必須相同、♣3 開局且不能 Pass、連三 Pass 的輪替與清檯、計分階梯與 2 的加倍（滿手 13 張含四張 2 = 52×16）、發牌 52 張守恆、相同種子碼重現同一局、`turnsToEmpty` 的分組正確、三種難度確實打出三場不同的牌局，以及**三種難度確實有強弱排序**（差異的 95% 區間必須越過零，1,000 局）。
