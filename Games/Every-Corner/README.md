## 走透透（Every Corner）

單筆路徑邏輯解謎：從 **1** 開始畫一條線，依序經過每個數字，而且 **必須走滿每一格**。不能交叉，不能穿牆。

規則三句話講得完，難度全部藏在「走滿每一格」裡——路線一旦把某塊區域切成孤島就再也回不去。玩家真正在做的事不是找路，是 **不斷檢查自己有沒有把未來的自己困死**。

> 玩法概念取自 LinkedIn 的每日解謎 Zip。**本作為原創實作**：自行出題、自行設計難度與介面，不使用對方的題目、名稱或任何品牌識別。

## 難度

| 難度 | 盤面 | 檢查點 | 牆 |
|------|------|--------|-----|
| 輕鬆 | 5×5 | 7 | 6 |
| 普通 | 6×6 | 9 | 12 |
| 困難 | 7×7 | 11 | 18 |
| 專家 | 8×8 | 14 | 26 |

**牆才是真正的難度旋鈕，不是檢查點數量。** 實測下來，1 道牆的 6×6 平均要放到 24 個檢查點才會有唯一解——36 格裡 24 個數字那是連連看不是解謎。同一個盤面放 12 道牆只需要 9 個。牆直接砍掉競爭路徑的數量，這才換得到稀疏又耐解的盤面。

---

## 出題：先畫答案，再把題目藏進去

要同時保證 **有解** 與 **唯一解**，正著出題幾乎不可能，所以整個生成器是反過來跑的。

**1. 隨機 Hamiltonian 路徑用 backbite（回咬）**

從蛇行路徑開始，每次取一個端點、隨機選一個鄰格、把中間整段反轉。**每一步都保持「走滿全盤且每格恰好一次」的不變式**，所以永遠不會失敗、不需要回溯。隨機回溯法在 8×8 上會一直卡死重來。

**2. 牆只放在答案沒走過的邊上**

先決定答案再決定牆，牆就不可能破壞答案。反過來先放牆再找路徑，在 8×8 上會經常找不到。

**3. 唯一解驗證，不唯一就補在分岔處**

窮舉但一數到 2 就提前結束。有兩解時，把新的檢查點補在 **對手解第一次離開正確答案的位置**——比較對象必須是答案本身，量兩個對手解之間的差距會得到「它們的」索引，打不到歧義點，永遠收斂不了（這就是第一版的 bug）。

**4. 取多次嘗試中最稀疏的一盤**

跑 14 次，一達到目標檢查點數就收工，否則保留最稀疏的。實測 2–6 ms 出一題，四種難度全部正中目標。

## 解題器的三種剪枝

沒有剪枝，8×8 不可能搜完。三種剪枝各自對應一個人類看得出來的死局：

| 剪枝 | 對應直覺 |
|------|----------|
| 連通性 | 「這樣走會把左下角孤立起來」 |
| 死路格 | 「那一格會變成有進無出的死巷」 |
| 終點唯一 | 「路線只能在最後一個數字收尾」 |

這也正好是 **提示系統的語言**：卡關時第一段提示說的是「你從第 7 步就偏掉了」，而不是直接告訴你往哪走。

## 操作

| 操作 | 手機 | 鍵盤 |
|------|------|------|
| 畫線 | 從 1 按住拖曳 | 方向鍵 |
| 擦除 | **往回拖到上一格** | <kbd>Backspace</kbd> |
| 提示 | 提示鈕 | <kbd>H</kbd> |

往回拖即擦除，所以手機上不需要另外按復原鍵。

## 每日挑戰

以當天日期（台北時間）導出種子碼，所有人解同一題。本地記錄完成時間、提示次數與 **連續天數**——連續天數在當天還沒解時仍然算昨天為止，不會在午夜前就被判斷失敗。

```bash
npm run setup            # 於 repo 根目錄，安裝一次
cd Games/Every-Corner
npm run dev              # http://localhost:3000
npm run lint             # tsc --noEmit
npm run check            # 邏輯自我測試
npm run build            # 輸出到 dist/
```

## 邏輯自我測試

`npm run check` 共 11 項。其中最重要的一項是 **剪枝版與無剪枝暴力版解題器必須回報相同的解數**——剪枝寫錯會安靜地砍掉正確解，而題目看起來完全正常，玩家只會覺得「這題好像無解」但說不出哪裡怪。

其餘涵蓋：回咬不變式與混合程度、每題恰好一解、解題器找到的解就是生成器那條、檢查點沿答案遞增且 1／N 落在頭尾、答案不穿牆、答案覆蓋每一格、相同種子碼生成相同題目、難度階梯、提示定位到正確的錯誤步數、連續天數跨月與斷線判定。
